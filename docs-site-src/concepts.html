Concepts

These ideas explain the design. They also explain why the repository checks itself.

Harden the codebase, not the agent

An agent forgets, drifts and guesses. A repository does not. So the repository holds the guardrails.

Hooks, CI jobs and lint scripts run every time. They need no memory of earlier sessions.

The plugin registers {{hooks}} hooks. They run with no model call. One hook denies a small set of catastrophic shell commands. The other formats a file after an edit. The first is an accident guard, not a security boundary.

Guidance is not a guardrail

A line in a prompt is a request. A model can ignore it. A script that exits with a non-zero code is a guardrail.

Test for any rule: can a script fail a pull request that breaks it? If not, treat the rule as a wish.

So the project prefers a check over a sentence of advice. Prose stays where judgment is needed.

Every mistake becomes a deterministic rule

When a mistake happens, the fix is not a reminder. The fix is a check that rules out the whole category.

A test then proves that the check can fail. A check that cannot fail proves nothing.

The file docs/mistakes-to-rules.md records each mistake next to its rule and its test. Here is one real row.

CI runs {{checks}} numbered checks: {{guardChecks}} inside the consistency guard and {{standaloneChecks}} standalone scripts. The CI checks page lists them all.

Static evals and live evals

A live eval runs a real model session. It shows what a model does with a skill. It costs money, so it runs only on request.

A static eval runs no model. It checks that the scripts pass and that every rule line is still present.

Today the plugin holds {{tiers.live}} live stamps and {{tiers.static}} static stamps. It holds {{tiers.waived}} waivers.

The Eval tiers page shows the tier of each skill.

Why scripts replace prose

A prompt that says "count the rows" invites a wrong count. A script counts the rows the same way every time.

So a skill hands exact work to a script. The skill keeps the judgment and the script keeps the arithmetic.

The plugin ships {{sharedScripts}} shared scripts and more inside skills. The Plugin scripts page shows the usage text of each one.

What is not verified

This project checks a lot. It does not check everything. These limits are real.

  • A static stamp says the tooling is intact. It does not say that a model follows a skill.
  • A rule inventory proves that the rule text is present. It does not prove that the rule keeps its meaning.
  • The sentence check measures length only. It does not prove that prose is clear or true.
  • The message check is a pattern proxy. It cannot judge whether a fix is correct.
  • Some mistakes still depend on human review. The second table in docs/mistakes-to-rules.md names them.

A static stamp never says that the model behaves. Read it as a statement about the tooling.
