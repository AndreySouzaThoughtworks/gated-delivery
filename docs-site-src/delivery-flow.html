Delivery flow

One ticket becomes small slices. Each slice merges on its own. This page walks the flow and shows real script output at each stage.

The flow in one view

You run /spec first. It turns a ticket into a signed-off spec. The spec holds an ordered Rollout of slices.

Then you run /slice. It reads the state of the ticket and picks a route. Then it does one bounded job and reports.

  • Ticket. A script lints the draft before the skill shows it.
  • Spec. A script lints the spec before you see the final draft.
  • Route. A script reads Git and the tracker. It names the route.
  • Claim. A script creates the slice branch and tree. It claims them on origin.
  • Batches. The slice-executor agent writes tests and code. Scripts audit each batch.
  • Review. Validators, a structural lens and a fresh-context reviewer check the slice.
  • Pull request. A script plans the commit and checks the PR body and title.

The model keeps the judgment. A script does each exact check. The sections below show the real output of those scripts.

The build ran every script on a fixture repository. No model ran, and no real tracker was used. The gh program was a stub for the route example.

Stage 2: write the spec

/spec walks the template with hard checkpoints. It writes the file only after you sign off.

A ticket gets one spec. A second run stops.

Three outcomes of the route step

The route table in /slice step 3 has several rows. This page groups them by what the skill does next. The grouping is ours. The table itself is in the skill file.

  1. Stop and hand back. Routes A, B, R and E do one bounded job. Then they stop.
  2. Do the slice work. Routes C, W and D run a slice, a wave or a resume.
  3. Close the ticket. Route F runs the ticket-end steps.

Route B′ is a pause. It returns to the route step once the spec is updated.

Outcome 1: stop and hand back

Routes A, B and R fix a gap in the spec and stop: no spec, open decisions or no Rollout. Route E waits for a merge. The skill does not invent merge boundaries while it executes.

Outcome 2: do the slice work

The spec is ready and a slice is free. A wave runs each slice in its own tree. A resume merges main in first when a sibling slice merged.

Outcome 3: close the ticket

The last slice has merged. The skill harvests the handoff and completes the Done-when list.

Route B′ is the pause. A new finding changes the architecture, the scope or the slice boundaries.

STOP rules

A STOP rule ends the run and surfaces the state. The rule inventories mark each one with the kind stop.

The Trust page counts these rules and shows how well they are protected.

Stage 4: claim the slice

slice-claim.mjs creates the slice branch and its tree. It commits an empty claim and pushes it as a create-only push.

The fixture has a bare origin and one clone.

Now a second person tries the same slice. The branch already exists on origin, so the claim is refused.

Exit code 4 means the slice is held. The skill must not retry.

Stage 5: executor batches

A batch is one dispatch of the slice-executor agent. It holds ACs that share one test subject. The agent writes one failing test, the code and one commit for each AC.

Before each dispatch the skill runs executor-preflight.mjs. The spec in the fixture has no acceptance criteria, so the script refuses the batch.

After a batch commits, the skill runs batch-audit.mjs on the range of that batch. The fixture holds one commit that breaks two rules.

The skill fixes each violation in a follow-up commit.

Stage 6: review

Review happens at two points. After each batch the skill runs a structural lens. At the end of the slice it runs more gates.

  • Stack validators that the client lists for its stack.
  • The full verify command, through the verify lock.
  • The senior-review-lens skill over the whole slice.
  • The code-reviewer agent, with a fresh context. It sees only the diff and the acceptance criteria.

The reviewer must run the checks itself. It may not report a pass on checks it did not run.

Stage 7: commit and pull request

commit-plan.mjs reads the commit convention of the client. It prints the subject form and the path of the PR body file. The fixture holds a client convention with a ticket key.

Before the PR is ready, pr-gate.mjs checks the body and the title. This fixture has a bad title. Its body also holds a closing keyword, but the slice is not the final one.

Each non-empty field is a defect. The skill fixes it and runs the gate again.

Merge is yours

The skill reports the ready pull request and stops. You decide when to merge.

The next /slice run cleans up merged slice trees. It then picks the next route.
