The problem

A model writes code faster than a person can review it. Teams pick one of three answers.

  • Review every line. A person reads each line that the AI writes. This is slow. Review becomes the bottleneck of the whole team.
  • Read a bit and hope. A person skims the change and hopes that the rest is fine. Hope does not change the outcome.
  • Deterministic rules. Automated checks prove what code can prove. People review only the results and the important choices.

gated-delivery is the third column. Scripts and CI checks carry the rules, so people spend their time on decisions.

How it works in four steps

  1. Spec. /gated-delivery:spec turns a ticket into a spec. The spec lists PR-sized slices in order. It writes nothing until you sign off each section.
  2. Slice. /gated-delivery:slice builds one slice at a time. Each slice gets its own branch and pull request. Independent slices run in parallel worktrees.
  3. Prove. Scripts, a design review and a fresh-context reviewer check each slice. The reviewer sees only the diff and the criteria. It runs the checks itself.
  4. Merge. A person merges each pull request. /slice never merges. Run it again for the next slice.

The skill sets each step. Scripts do the exact parts, such as the commit audit and the pull request gate. Models do the reviews. A failing step sends the work back to be fixed.

What it is

gated-delivery turns one tracker ticket into slices of work. Each slice merges on its own.

The plugin ships {{skills}} skills, {{agents}} agents, {{commands}} commands and {{hooks}} hooks. It also ships {{shippedScripts}} script files: {{sharedScripts}} shared scripts, {{skillScripts}} inside skills and {{bootstrapScripts}} for bootstrap.

The plugin has no client baked in. Your repository supplies the client facts in its CLAUDE.md. The facts cover the tracker, the commit convention and the verify command.

Why it is different

A prompt is a request, and a model can ignore a request.

gated-delivery moves the rules into the repository. A hook, a script or a CI check enforces each rule. Enforcement does not depend on the memory of a model.

  • Deterministic rules. CI runs {{checks}} numbered checks: {{guardChecks}} inside the consistency guard and {{standaloneChecks}} standalone scripts.
  • Rules that can fail. A mutation score shows that deleting a rule line gets caught.
  • Honest evidence. The plugin holds {{tiers.static}} static stamps and {{tiers.live}} live stamps. The site says so openly.

A rule that no script can fail is a wish. This project turns wishes into checks.

Prompt versus skill

A prompt is a request in a chat. A skill is a file in the plugin, with scripts and checks around it.

QuestionA promptA skill in this plugin
Where it livesIn a chat history.In a versioned repository, under plugin/skills.
When it stopsWhen the model decides it is done.At checkpoints where a person approves. /spec writes after sign-off. /slice never merges.
What enforces itThe attention of the model.Scripts that the skill calls, hooks that Claude Code runs, and CI checks on the repository.
How we know it worksYou read the output.{{tiers.static}} static stamps and {{mutationScored}} mutation-tested rule inventories. Live evals are not run.
Who benefits from a fixOne person.Everyone who updates the plugin.

Try it in four steps

  1. Install. Add the marketplace and install the plugin with the two commands below. Then run /reload-plugins.
  2. Add client facts. Put the tracker, the commit convention and the verify command in the CLAUDE.md of your repository. The client context lists each section.
  3. Spec a ticket. Run /gated-delivery:spec PROJ-123 with a real ticket key. Sign off each section.
  4. Slice it. Run /gated-delivery:slice PROJ-123. Merge each pull request when it is ready. Run the command again for the next slice.

Start small: one ticket, end to end.

Install in two commands

Run the first command in a shell. Run the second command inside Claude Code.

claude plugin marketplace add andrey1souza/gated-delivery /plugin install gated-delivery@gated-delivery

Install at user scope. Then run /reload-plugins so the agents register in the running session.
