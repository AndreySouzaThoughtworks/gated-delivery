Install and update

Install the plugin and reload it. Update it with one command. This page also explains the version, the Node policy, the environment variables and profiles.

Install

Run the first line in a shell. Run the other two lines inside Claude Code.

claude plugin marketplace add {{repository}} /plugin install {{pluginId}} /reload-plugins

Install at user scope. Then run /reload-plugins. Without it, the agents stay unregistered in the running session. Claude Code then reports agent type not found.

To check the install, run claude plugin list and look for Scope: user.

The sources are README.md and docs/onboarding.md.

First commands

These are the commands you run most. Replace PROJ-123 with a ticket key from your tracker.

/gated-delivery:bootstrap /spec PROJ-123 /slice PROJ-123 /gated-delivery:commit /gated-delivery:commit-push-pr

The bootstrap command adds missing guardrails to a client repository. It shows a plan and writes nothing until you confirm each group.

The spec skill writes the spec. The slice skill runs the slices. The Delivery flow page shows both. The Commands page lists every command.

Update

claude plugin update {{pluginId}} /reload-plugins

The command /plugin update does the same inside Claude Code. Run /reload-plugins after it.

What the version string means

With no version field, Claude Code uses the commit SHA of the repository as the version. The source is the comment above check 15 in scripts/audit/consistency.ts.

So every commit on main is a new version. A commit that changes only documents is still a commit. It is a new version too, even when no plugin file changed.

The update command fetches that new version. A user may see an update with no change in behaviour.

This is on purpose. A pinned version froze installs once.

Check 15 fails when a manifest holds a version. See it on the CI checks page.

Node policy

The plugin hooks and scripts run as node file.mjs on your machine. They need Node {{nodeFloor}} or later. That is the oldest release that still gets security fixes.

You need Node {{nodeDevFloor}} or later to work on this repository. That release strips TypeScript types, so the dev scripts need no build step.

The floor reaches end of life on {{nodeFloorEndOfLife}}. Then the policy says to raise it.

The table comes from NODE_END_OF_LIFE in scripts/audit/node-floor.ts. The floor comes from engines.node in package.json.

Check 31 enforces the policy. It fails when the floor reaches its end-of-life date. It fails when a document names another floor.

A release below the floor is end of life. No job tests it. The source is docs/development.md.

One profile per client

Each CLAUDE_CONFIG_DIR is a separate Claude Code profile. It has its own login, plugins, memory and history. Install the plugin into each profile that you use.

export CLAUDE_CONFIG_DIR=~/.claude-personal claude claude plugin marketplace add {{repository}} claude plugin install {{pluginId}}

Run /login once in the new profile.

The skills keep notes and review trees in a machine-local folder. Allow that folder once for each profile. Add this line to the settings.json of the profile.

Keep client plugins, MCP servers and the client CLAUDE.md in that client profile only.
