Why gated-delivery

This page explains why the project exists, what it bets on, and where the bet is not proven.

The human bottleneck

This project starts from one premise. A model writes code faster than a person reads it.

The queue then moves to review. One large pull request that a model wrote in one shot is slow to read and easy to skim. A person who skims is reading a bit and hoping.

gated-delivery shrinks the queue in two ways.

  • Smaller changes. /spec splits a ticket into PR-sized slices. Each slice merges on its own.
  • Fewer questions for people. A script answers each question that a script can answer. A person reviews the results and the decisions.

The skill that runs a slice stops at checkpoints. A person approves the spec, reviews the slice and merges the pull request. The Features page shows each stop.

A skill, not a prompt

A good prompt lives in the head of one person. The same ticket gets a different result from each person who prompts it.

A skill is a file in a versioned plugin. The team reviews it like code. The plugin has no version field. Each commit on main is an update, and claude plugin update {{pluginId}} fetches it. When someone improves a skill, everyone gets the change on the next update.

The comparison on the home page sets a prompt next to a skill on five questions.

Rules live in the repository, not in the memory of an agent

An agent forgets, drifts and guesses. A repository does not. So the repository holds the rules, and a machine enforces them.

The project applies the ladder to itself.

  • Scripts replace prose. The plugin ships {{shippedScripts}} script files. A script counts rows and checks files the same way every time.
  • CI checks. CI runs {{checks}} numbered checks. A fixed mistake becomes a check that rules out its whole category. The Mistakes page also lists the mistakes that still have no rule.
  • Ratchets that only shrink. Baseline files for lint findings, weak messages and unproven assertions may shrink. They may not grow.
  • Actionable messages. A check fails with the rule, the cause and the fix. A pattern check holds that line.
  • A token budget. Each instruction file has a budget. A file that grows past it fails CI.
  • Plain documents. A script grades the docs. At least 80% of the sentences must have 20 words or fewer. The style is ASD-STE100.

The Trust page shows each mechanism with its live numbers. The CI checks page lists every check with a real message.

Honest evidence: what is proven and what is not

A project that sells discipline must not overstate its own proof. This is the state today.

What the repository proves

  • {{inventories}} rule inventories pin {{rules}} load-bearing rules to literal anchors in the skill, agent and command files.
  • A mutation script deletes each anchored line. {{mutationPerfect}} of {{mutationScored}} inventories catch every deletion.
  • Each skill carries a stamp. The plugin holds {{tiers.static}} static stamps: the scripts and checks of each skill pass.

What it does not prove

  • The plugin holds {{tiers.live}} live stamps. Live evals are off, because they spend the maintainer's subscription. So no run shows that a model follows each skill.
  • A rule inventory proves that the rule text is present. It does not prove that the rule keeps its meaning.
  • The plugin scripts run in tests against a stub of gh. One opt-in test uses the real gh.
  • The sentence check measures length only. It does not prove that a text is clear or true.

A static stamp says that the tooling is intact. It never says that the model behaves.

The Trust page and the Eval tiers page hold the full list.

Who it is for

  • Teams that ship tickets with Claude Code. The work starts from a ticket in a tracker. The skill for tickets has adapters for GitHub and Jira.
  • Teams that want small pull requests. A reviewer sees one slice at a time, with the checks already run.
  • People who work for many clients. The plugin names no client. Each client keeps its facts in its own CLAUDE.md and its own Claude profile.
  • Maintainers who want guardrails. The /gated-delivery:bootstrap command plans the missing guardrails of a Python or TypeScript repository. It writes only after you confirm each group.

What it is not

  • Not an agent framework. It runs no agent runtime of its own. It is a set of skills, agents, commands and hooks for Claude Code.
  • Not a replacement for review. /slice stops for a person. A person signs off the spec, reviews the slice and merges the pull request.
  • Not a test runner. It runs the verify command that your repository names. A repository with no tests gives the gates nothing to run.
  • Not a security boundary. The Bash guard denies a small set of direct, literal commands. Indirection such as bash script.sh passes it by design.
  • Not proof that a model obeys. It moves each rule that a script can check out of the prompt. It cannot make a model follow a rule that only prose holds.
